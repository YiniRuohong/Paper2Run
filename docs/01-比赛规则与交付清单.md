## 📋 核查结论与证据边界

Paper2Run 与公开资料中的“效率进化”赛道、阿里云特别赛题“基于 Qwen 大模型的科研提效：认知增强与研发范式革新”相符，建议按这个方向继续规划。两份公开赛事收录资料均写明 2026 年赛期，但它们都不是主办方第一方规则。不能把“两个网站一致”理解为两个独立官方确认。[^1][^2]

本次访问用户提供的天猫官方活动入口，确认页面标题为“AI黑客松”，但正文被登录弹窗和滑块验证阻挡。没有绕过验证，没有登录、报名、提交作品或发表内容。因此，**完整官方规则及报名后台操作尚未核实**。[^3]

本文采用三个证据等级：

- **A：第一方已读取。** 本次只确认官方入口及访问限制，没有读到完整活动规则。
- **B：公开转载线索。** 可用于暂定规划，但在参赛合规决策前仍应核对第一方。
- **U：未知或待确认。** 不补写成规则，不用历史聊天或 PRD 的说法代替官方证据。

### 赛道和项目对位

公开介绍写明四大赛道开放自由创作，也设置特别赛题；提交时需选择赛道并说明关联。四赛道为效率进化、智能日常、创意造物、科技无碍。[^1]

建议参赛说明使用：

> Paper2Run 面向需要验证论文方法的研究生与算法工程师，用 Qwen 将论文实验描述整理为可核对的实验协议，生成受控实验代码，在隔离环境执行并依据真实评测形成证据报告。它把“理解论文—搭建实验—定位错误—验证结果”连接成可追溯的科研操作流程。

Qwen 在特别赛题名称中明确出现。因此本方案让 Qwen 承担实际解析、规划和代码修复，而不是只在页面放一个标志。**这不等于已经证实所有赛道都强制使用 Qwen。** 是否限定特定模型、阿里云调用渠道、最低使用占比或 AIPC 硬件，仍需特别赛题原文确认。

### 提交和评审已知范围

公开资料记载初赛线上提交“创意 Demo 及项目方案”，专业评审与线上人气共同决定晋级；决赛在初赛 Demo 基础上迭代并路演。[^1][^2]

本次没有核实到：创新性/实用性/完成度各自的官方分数、专业评审与人气的百分比、所谓“美观度加分”、端云协同加分。产品仍应重视这些品质，但应标为**工程与展示策略**，不能写成官方评分标准。

## ⚙️ 报名与提交操作检查

已核实到的公开入口指引只有“淘宝 App 搜索‘天猫AI黑客松’”和用户提供的天猫页面链接。[^1][^2] 下面是**建议的人工检查顺序**，不是本次实际见到的按钮名称或已完成操作。

1. 进入官方活动页，登录本人已报名账户，核对赛事届次与队伍记录。
2. 打开活动规则、特别赛题说明和作品提交说明，保存原文件或截图，记录版本与查看时间。
3. 核对队员信息及赛道；不要因为已经报名就假定作品已经提交。
4. 按实际字段填写项目名、问题定义、Qwen 使用环节、Demo 和附件；不要提前发布无权公开的论文全文或数据。
5. 若有草稿/预览功能，先检查视频、下载与评委访问权限。在线演示不应要求评委提供自己的模型 Key。
6. 正式提交后确认平台成功状态、项目编号、时间和可修改期限，留存回执；如果有二次确认，完成后再记录“已提交”。
7. 在允许的设备或未登录窗口测试评委访问路径。不要通过刷量或自动投票提高人气。

主办方后台字段和流程若与上述检查顺序不同，以后台实际说明为准。

## 📦 建议提前准备的材料

以下是项目自己的交付包，**并非断言它们全部为赛事必交**。

| 材料 | 内容边界 | 验收方式 |
|---|---|---|
| 项目方案 | 问题、目标用户、范围、技术架构 | 与真实产品一致 |
| 可运行 Demo | PDF 到证据报告的完整路径 | 无痕窗口可进入 |
| 演示短片 | 正常、修复、不可比较三种路径 | 总时长符合后台规格 |
| 源码与运行说明 | 锁文件、配置示例、无密钥 | 干净机器可复跑 |
| 实验案例包 | 协议、代码、日志、权重、评测 | 哈希和结果可追溯 |
| Qwen 使用说明 | 模型配置、调用环节、用量记录 | 去除所有敏感信息 |
| 授权与贡献说明 | 第三方依赖、数据和团队分工 | 许可证清单齐全 |
| 现场备用材料 | 本地视频、真实历史报告 | 明确标为回放 |

建议展示的唯一核心亮点：**同一篇论文，先让用户看见实验依据，再让评委看见真实失败如何被修复，最后能从指标返回原文和独立评测证据；条件改变时系统拒绝虚假“复现成功”。**

暂按“问题 30%、演示及证据 70%”编排讲解，这是借鉴黑客松技能后的内部表达建议，不是官方时间比例。最终片长与路演时长尚未核实，不预设为 3 分钟或 5 分钟硬限制。
