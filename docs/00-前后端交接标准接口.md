# Paper2Run 前后端交接标准接口

_浏览器公共 API 与前端 GUI 联调入口。_

本文定义“前后端交接标准接口”的阅读入口；具体 DTO、请求/响应、SSE 事件、Mock 数据约束、页面状态和联调规则以两份专题文档为准。

## 1. 标准接口契约

- [前后端公共接口契约 v0.2](09-前后端公共接口契约.md)：浏览器 `/api/v1` 的统一 DTO、请求/响应、错误、鉴权、SSE、分页、幂等、Mock 和联调规则。

## 2. 前端 GUI 交接

- [前端 GUI 交接说明](10-前端GUI交接说明.md)：页面结构、前端职责、视觉状态、Mock 模式、组件边界、联调流程和交付检查。

## 3. 必须遵守的边界

- 前端只访问浏览器公共 API `/api/v1`，不得直连模型、OSS 管理接口、数据库、Docker 或 `/internal/v1`。
- 浏览器不接触模型 Key；服务端负责 ID、hash、权限、实验判断、任务状态、数字和评分。
- 前端负责输入、展示、交互及状态反馈；不得在组件中自行补默认算法配置或篡改服务端协议字段。
- `run.status=completed` 不等于 `verdict=matched`；未知值为 `null`，不得显示为 0。
- 当前项目只有设计和静态原型，没有在线 API、Swagger 或可运行后端；接口示例和 Mock 数字不得作为真实实验结果。

## 4. 联调顺序

1. 前端先阅读本文和 [前端 GUI 交接说明](10-前端GUI交接说明.md)。
2. 后端以 `09-前后端公共接口契约.md` 生成 Pydantic → OpenAPI → TypeScript 类型链。
3. 前端只消费生成类型，并用 `mock-ui` 验证页面状态和 SSE 状态转移。
4. 后端完成 `local-cpu` 后再进行真实 API 联调；`remote-gpu` 和 `replay` 必须在页面中明确标示运行模式。
