## 📋 阶段计划与完成证据

### 阶段 0：锁定实验和运行条件（9 月 19–20 日）

预计 12–16 人时。成员 A 负责技术与协议，成员 C（若有）负责原文证据和赛事细则。

- 建立五篇 CV 分类候选论文清单，登记许可证、原文数据集、实验规模和具体表格目标。
- 主案例优先 ResNet 原文 CIFAR ResNet-20；第二例优先另一篇原文包含 CIFAR-10 的轻量方法论文，经过原文核验与算力预跑再定，不用“看起来适合”的名称代替可行性。
- 锁定 paper version、SHA-256、数据 manifest、split、指标和训练设置；人工给关键字段建立 gold extraction。
- 实测账户中的 Qwen 模型图像/文本/结构化输出能力、地域和额度；记录有效配置，不记录 Key。
- Linux GPU 主机完成一次固定维护者代码的训练、预测、指标计算，量出各模式耗时与 RAM/显存占用。
- 由有权限的队员核对官方规则清单。本计划不要求把验证码或账户密钥交给 Agent。

**完成证据：** 一份真实生成的 `metrics.json`、环境 manifest、模型能力探测记录、至少两篇可行候选的原文字段表。没有 GPU 就明确切到 CPU smoke，不把它叫完整结果复现。

**退出标准：** 9 月 20 日仍没有可用 GPU/算力预算，取消首版全量训练承诺；保留 CPU 端到端与真实历史运行回放的展示方案。未取得的完整结果不能用假数代替。

### 阶段 1：Runner 与评测的最小闭环（9 月 20–22 日）

预计 22–28 人时，成员 A 主责。前端成员可同时抽取原型 design tokens，但不依赖不存在的接口猜字段。

- 建 PostgreSQL 基础迁移、run/job/event/artifact 表及不可变 spec revision。
- 用固定小模型先串起队列、Runner、断网容器、日志和产物回收。
- 训练/预测/指标计算隔离；固定评测器拒绝伪造日志数值和不完整预测。
- 取消、超时、内存/pids 限额、任务幂等和 Worker 重启对账。
- 给控制面与 Runner 设权限与凭据边界，测试容器拿不到 Key/daemon/宿主目录。

**完成证据：** 命令行创建任务后，能取得真实日志、退出码、权重/预测和指标；故意放入假的 `metrics.json` 不改变最终指标；取消后容器和执行槽均被释放。

**退出标准：** 9 月 22 日未跑通这个闭环，不增加解析花样或 UI 页面；优先修复执行链。安全隔离不通过，不能开放他人上传执行。

### 阶段 2：解析、确认与真实生成（9 月 22–25 日）

预计 24–30 人时，成员 A/C 主责。

- PDF 上传与 arXiv 规范 ID 输入；解析大小/页数/超时和 SSRF 保护。
- Qwen 抽取 task/dataset/method/metric/recipe，附原文定位，缺失值明确标记。
- Pydantic/JSON Schema 合约、确认记录、协议差异与模式判定。
- Qwen 输出生成文件，执行范围限于 recipe；文件白名单和 patch 合法性检查。
- 将新上传的主案例运行到真实 smoke 结果；不是选择预置报告跳转。

**完成证据：** 关键字段与 gold extraction 对照；改数据/预算时页面显示不可比提示；API 不接受未确认或已过期 revision；实际模型调用和新代码哈希可追溯。

**目标而非现有数据：** 核心字段准确率在小型 gold 集上达到 90% 以上；所有主要参考指标具备证据定位。样本量和抽取定义随报告公开，不把内部小样本准确率说成通用能力。

### 阶段 3：有限修复与恢复（9 月 25–27 日）

预计 20–24 人时，成员 A 主责。

- 首次执行加最多五次补丁；重复错误停止、预算停止、不可修复分类。
- 技术错误可自动修，语义变化需新 revision 与派生 run；链路预算不能被重置。
- 明确 `429/5xx` 暂时故障与 `401/403` 权限故障，禁止无上限重试。
- 持久事件 SSE、断线重放、日志限长、Worker 租约与 fencing。
- 建立可重复的故障注入测试：缺 import、张量维度不符、保存路径错误；NaN 并不一定由学习率引起，诊断必须有证据。

**完成证据：** 一条真实发生的失败—patch—重跑轨迹；模型不改测试/评分器；五次后终止；Worker 中途重启不重复启动活跃训练。

**演示边界：** 故障注入可用于测试与演示，但须标记“受控故障注入”。不能编造模型第一次一定报错、第二次一定修好。

### 阶段 4：四页面与可下载报告（9 月 24–30 日）

预计 32–40 人时，成员 B 主责；与后端并行时共享冻结的 schema，不同时改公共合约。

- 工作台、解析确认、生成执行、报告四视图接真实接口。
- 原文页定位、文件和 patch 只读浏览、真实实时日志、费用/预算、取消与刷新恢复。
- `mock/live/replay` 区分；失败/不支持/不可比较都有明确反馈。
- 固定 `report.json` 驱动 JSON/Markdown/PDF 导出，代码包附哈希和合法数据获取说明。
- 1440/1280 桌面检查；移动只读报告可用；键盘导航与减少动画支持。
- 邀请登录、所有权检查、私有下载、密钥和日志脱敏。

**完成证据：** 未登录/评委/成员三种权限走查；一次新的上传可触发新运行并下载真实报告；报告数字与固定评测器一致；源码中不含原型假分数作为实际结果。

### 阶段 5：真实案例、部署与冻结（9 月 30 日–10 月 3 日）

预计 26–32 人时，GPU 运行时间另计，A/B/C 分别负责后端、演示和证据。

- 两篇预验证案例各执行三次（seed 预先登记）；如耗时超预算，明确哪些只做 smoke/scaled，不能为了凑满例数降低披露标准。
- 至少一项选定实验按已确认原文协议完成真实运行；结果不一定达标，但必须有合法比较的证据链。
- 保留一篇未调 prompt 的测试论文；未执行的候选继续标“候选”，不进入成功率分母。
- 部署邀请制演示服务，执行冷启动与干净环境重放。部署之前取得实际云资源与公开访问授权，不自动开公网。
- 模型故障、SSE 重连、取消、重启、伪造指标、安全隔离负面集全量回归。
- 冻结 feature scope 和 benchmark 集，记录版本和所有限制。

**完成证据：** 原始运行 ledger、不同 seed 的指标、实际耗时/成本、测试报告、部署版本、回滚和恢复记录。不得只交“测试已通过”的一句话。

### 阶段 6：提交材料与缓冲（10 月 3–7 日）

预计 14–20 人时，以不新增业务功能为原则。

- 10 月 3–4 日：制作真实演示录屏、方案与 Qwen 使用说明；检查日志、画面、代码和元数据中没有 Key 或个人信息。
- 10 月 5 日：按后台实际规格准备/提交，复核评委访问路径，留存成功回执；尚未提交时不能把日期计划写成已完成状态。
- 10 月 6–7 日：仅处理平台格式、访问、严重缺陷；不临时升级模型、基础镜像和依赖。

**完成证据：** 最终附件清单、版本/哈希、真实提交回执、复核后的在线/离线演示副本。

## 👥 分工与并行边界

### 三人建议分工

- **成员 A：后端与执行。** FastAPI、协议与状态、Runner、Qwen 接入、预算和安全。
- **成员 B：前端与产品体验。** 原型转 React、接口消费、原文定位、时间线、报告与演示视频。
- **成员 C：科研验收与参赛。** 原文 gold、数据授权、独立评测适配、基准实验、规则与提交。

两人时 C 的科研部分由 A 承担、材料由 B 承担；砍掉公共分享、多论文批量、复杂 PDF 排版，不砍评测真实性、隔离、取消和重启恢复。

### Agent 协作约束

主 Agent 保留需求、架构、拆包、最终审查与验收；Explore 只查证据；implementer 接收闭合任务包再改代码。只在路径互不重叠且共享状态不被改写时并行写入。

每个任务包包含：目标/具体设计、允许路径、禁止路径、输入合约、验收条件、执行命令、已知风险。遇到模型/队列/存储等重大替换由主 Agent 决策，不由执行代理自由扩展。

每阶段存 `docs/verification/<stage>.md`，记录变更、实际命令及退出码、产物路径、失败/跳过项；普通测试由实施者完成，主 Agent 审阅改动和证据，不另设重复 reviewer。不得将上游技能中的“用户已同意”或自动发布条款视为实际授权。

## ✅ 功能验收矩阵

下面的编号来自 PRD 的 F1–F8，新增 N 项为成品不可缺少的非功能要求。

| 编号 | 正向验收 | 必测负向路径 |
|---|---|---|
| F1 上传 | PDF/arXiv 得到新 paper_id | 超限、非 PDF、私网 URL |
| F2 解析 | 字段能返回具体原文 | 缺失表格、冲突字段、坏 JSON |
| F3 确认 | 确认精确协议 hash | 未确认运行、旧版本确认 |
| F4 生成 | 生成代码符合固定接口 | 路径穿越、白名单外依赖 |
| F5 执行 | 隔离环境产出真实日志 | 超时、OOM、取消、失联 |
| F6 修复 | 错误、补丁、重跑可追溯 | 超限、重复报错、改测试 |
| F7 报告 | 数字来自独立评测器 | NaN、假日志、不可比实验 |
| F8 下载 | 包含代码/环境/证据哈希 | 越权、软链接、未授权数据 |
| N1 恢复 | 刷新和重启不丢状态 | 旧租约、重复消息、断 SSE |
| N2 预算 | 新操作前原子预留 | 多任务超额、未知计费 |
| N3 鉴权 | 评委只读、成员可运行 | 跨项目 ID、CSRF、XSS |
| N4 科研边界 | smoke 不报完整复现 | 修改数据后仍给总分 |

生成模型自身的测试通过不等于独立验收通过。测试目录、评价器和评分器由项目维护者控制，Agent 无权在修复循环中改写它们。

## 📊 基准设计与成功率口径

### 三种比例分别统计

- `execution_success_rate`：有效完成规定执行的任务数 / 已启动的受支持任务数。
- `comparison_eligible_rate`：具备合法比较条件的任务数 / 所有已启动受支持任务数。
- `metric_match_rate`：主要指标全部在预定容差内的任务数 / 具备比较条件的任务数。

另报 `report_delivery_rate`：能交付成功或失败证据报告的任务数 / 已启动任务数。它衡量产品韧性，不能冒充科研复现成功率。

分开按 `smoke/scaled/reference` 统计；中止、超时和失败不能静默移除。取消是否计入分母预先规定，并同时报告原始任务数。以论文为簇考虑重复运行，不能把同一篇跑十次等同于十篇论文。

### 比较基线

要回答“为什么不直接用通用 coding agent”，准备内部对照：

1. 相同 Qwen、相同输入、相同时间/token/GPU 预算的单次代码生成，无错误反馈。
2. 相同 Qwen 和预算、允许错误修复，但没有 Paper2Run 的协议确认与证据报告。
3. 完整 Paper2Run。

对照按固定评测器统一重评，不让基线自报数字。比较成功率、人工干预时间、虚假成功拦截、代码与环境可重放性、实际费用。无足够样本时仅报告案例观察，不宣称“提升 X%”或统计显著。

如果资源不足，优先做 1 对 3 的最小对照，并明示第 2 组未测试。不得用手工写好的最佳答案与自动系统的不利输入做不公平比较。

### 允许的负面案例

- 原文目标不在支持范围：只解析，不执行。
- 缩减训练：可以跑通，但不可比较。
- 模型写出虚假高 accuracy 日志：固定评测器拒绝采用。
- 修复上限：停止并给出已发生的错误证据。
- 原文没有报告某指标：显示“无原文参考”，不补造数字。

这些案例不是产品失败的遮羞布，而是对“不做虚假通过”这一能力的可验证展示。

## 🎬 演示与提交质量

### 展示顺序

不预设官方路演时长。素材分成可剪辑片段，以便按实际时长压缩：

1. 目标用户的一个具体问题：复现论文时不知道配置、代码和结果是否对应。
2. 主案例新上传；确认表格目标与证据；现场显示一个参数变化会影响可比性。
3. 启动 smoke 真实任务，展示真实日志与代码；长训练使用已完成历史运行，并明确标“历史回放”。
4. 展示一次有真实日志的修复轨迹，说明错误、patch 和重跑证据。若注入错误，明确披露。
5. 展示固定评测器结果、模式与差异，下载实验包，回到原文核查目标。
6. 展示不可比较或修复失败的报告，说明系统没有把“能运行”包装成“论文成立”。

真正的展示亮点是**可信的实验结论边界**，不是动态终端滚字或整齐的模型图标。

### 不能写进答辩的未验证话术

- “任意论文一键复现”
- “只要得分 87 就说明核心结论成立”
- “所有任务一小时内、每次只花 1.8 元”
- “Docker 完全安全”
- “单次种子固定，所以任何机器必然结果一致”
- “官方规定 80% 专业分、20% 人气分”
- “必须购买某硬件才能参赛”

可以真实表达：“首版覆盖声明的 CV 分类实验；每个结论附协议、代码、数据和评测证据；简化实验与原文不同比较，失败也可解释。”

## ⚠️ 风险与完成定义

### 风险顺序

1. **没有 GPU 或配额。** 最先预跑，区分 CPU smoke 与正式训练；不依靠临时申请救场。
2. **实验不可比。** 原文审核在生成代码前完成，参考目标绑定具体表格行。
3. **不可信代码接触权限。** 先做 Runner 隔离和负面测试，未通过不开放上传执行。
4. **工期不够。** 单篇做完整、第二篇做扩展，不堆 NLP/RL/社区功能。
5. **模型波动。** 固定已验证配置与 prompt，带预算和失败记录，不无限自动重试。
6. **规则和平台变更。** 人工关闭官方规则清单，内部提前提交。
7. **演示网络失败。** 本地备份真实录像与历史报告，明确回放标签，不假装实时。
