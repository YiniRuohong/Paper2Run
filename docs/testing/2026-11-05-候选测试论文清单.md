## 2. 适配约束（选择与协议设计时的硬边界）

1. **评测指标**：独立评测器 `p2r_evaluation` 当前实现整数类 accuracy（bootstrap 置信区间）；benchmark 侧另有 purity 与 r2。选论文时指标应落在 accuracy / purity / r2 三者之一，或如实走 exploratory 模式（参照 diabetes-lars 场景的做法：`mode: exploratory` + `not_comparable`）。
2. **两条接入路径**：
   - **路径 A（benchmark 离线/在线模式）**：合成数据 + 纯 Python 实现（现有参考实现只 import `random/json/math`），沙箱 30 秒 CPU 上限。适合手写可实现的经典方法。
   - **路径 B（e2e 自主模式）**：真实论文 PDF + Docker 目标环境 + `pip install numpy scikit-learn` + 公开数据 raw URL（附 sha256 溯源）。适合 sklearn 有现成实现的方法。
3. **数据可得性**：优先 sklearn 内置小数据集（iris / wine / breast_cancer / diabetes 均内置或可从 sklearn GitHub raw 拉取）；复现老论文原文实验时若原文数据不可得，用公开同源数据并诚实标注 exploratory。
4. **CPU 预算**：n≈150–450 的小数据 + 经典方法均在 30 秒内；避免任何需要 GPU / 大预训练权重的方法。

## 4. 首批建议组合（5 篇即可覆盖三种指标 × 两条路径）

1. **LASSO + diabetes**（A 表 #1，路径 B）：现成 diabetes 管线的最小增量，直接对照 LARS 运行产物。
2. **Elastic Net + diabetes**（A 表 #2，路径 B）：测多超参协议抽取。
3. **Fisher 1936 LDA + iris**（B 表 #7，路径 B）：论文数据与测试数据同源，最干净的「真复现」用例。
4. **SVM + wine/breast_cancer**（B 表 #8，路径 B）：测「原文数据不可得 → 公开数据 + exploratory」的诚实报告链路。
5. **k-means++ + 合成高斯簇**（C 表 #14，路径 A）：扩充离线 benchmark（纯 Python），与迷你论文 05 直接对照，且不依赖任何模型服务。

## 5. 新论文落盘格式速查

- 路径 A（benchmark）：`tools/benchmark/papers/<NN-slug>/` 下放 `paper.md`（章节：任务/数据生成/方法/指标与声称区间/复现约定）+ `task.json`（`task_id/title/metric/claimed_low/claimed_high/seed/n_train/n_test/method/difficulty`）+ `reference_solution.py`（仅 `random/json/math`）。跑法：`python tools/benchmark/run_benchmark.py --mode offline --papers <NN-slug>`。
- 路径 B（e2e）：仿照 `.p2r-e2e-autonomous/fullflow/` 的场景结构，`requested-protocol.json` 按 `paper2run.protocol.v1` 填 objective/method/parameters(split)/data_sources（raw URL + sha256）；无论文参考指标时 `mode: exploratory` 并明确 `not_comparable`。
