# Paper2Run 自主实验框架改进工作文档

日期：2026-11-03

状态：已确认的需求基线；已进入实现与验收。本文保留原始产品范围和验收要求，当前代码架构见 [软件架构](../architecture.md)，实际测试证据与尚未验证的边界见 [13 号实施与验收文档](13-Paper2Run自主实验框架实施与验收.md)。下文的阶段清单为原始工作要求，不单独作为通过凭证。

**目标：** 将 Paper2Run 从固定配方、标准库近似实验的工作台，升级为基于成熟 Harness、可加载科研 Skills、可通过 SSH 自主开展真实实验的框架。

**架构：** Paper2Run 提供资料、配置、任务界面和持久记录；成熟 Harness 统一管理模型、工具、会话和实验推进；本地或远程隔离环境承载执行。SSH 由 Harness 的工具能力使用，不再另建一套独立的智能 SSH 编排器。

**技术基础：** 复用现有 React/TypeScript、Electron、FastAPI、Python >=3.11、SQLite 本地记录和产物存储。Harness SDK、连接实现和远程隔离技术通过阶段 0 验证后锁定，现有 Pi SDK + Extension 设计作为优先候选，不作为已经验证的依赖事实。

## 1. 已确认的产品决策

1. 采用成熟 Harness SDK 扩展路线，优先通过扩展接口定制，不先自研完整 Agent loop，不默认分叉上游内核。
2. 框架提供工具、上下文和过程支撑，不用固定分类 recipe 或 Python 标准库白名单限制科研内容。
3. 在已授权实验环境内，Agent 可以联网、获取代码与数据、安装依赖、编辑多文件代码、执行命令、排错和调节运行策略。
4. 首版远程算力由用户提前租好。框架接入已有 SSH 目标，不负责租机、续费、换实例或释放平台实例。
5. SSH 调用与实验决策交给 Harness。Paper2Run 准备可读取的基础配置、连接凭据引用、界面和记录机制。
6. 首版预装科研 Skills，并提供能力管理的基础；完整插件商店属于扩展方向，不是首版闭环的前置条件。
7. 复用现有论文处理、版本记录、事件、产物、报告和导出能力；运行完成不自动等于论文复现成立。

## 2. 当前实现与改造动机

当前真实流程包含上传、PDF 解析、模型会话、结构化抽取、候选选择、方案确认、环境检查、可选代码生成、运行、评测及导出。

| 当前机制 | 局限 | 改进方向 |
| --- | --- | --- |
| Provider 直接承担抽取和代码生成 | 缺少持续工具循环与现场探索 | 使用可恢复的 Harness 会话驱动任务 |
| 标准库、自包含单文件、无网络 | 无法承载常见深度学习依赖和真实数据 | 在实验隔离边界内开放工具与依赖 |
| 以注册 recipe 决定可执行候选 | 科研内容被已有配方限制 | 以通用实验协议和环境能力决定执行条件 |
| SSH 模拟校验和目标登记 | 未建立真实连接，不能远程运行 | Harness 使用真实 SSH 工具执行 |
| 分类预测、标签和准确率为中心 | 回归、生成、优化和仿真难以接入 | 可扩展的产物与评测协议 |
| 运行事件与本地记录 | 尚不足以保证长期远程任务恢复 | 持久任务标识、日志和断线重连 |

当前实现依据：

- [当前软件架构](../architecture.md)。
- [现有 Harness 规划](11-Paper2Run统一工程设计.md)，其中最小工具白名单与本文开放实验方向存在冲突。
- `apps/web/src/features/guided/RealFlowPanel.tsx`：现有引导流程与 SSH 边界。
- `packages/orchestration/p2r_orchestration/codegen_service.py`：标准库、无网络、自包含代码限制。
- `packages/orchestration/p2r_orchestration/ssh_executor.py`：FakeSSHVerifier，不发生真实网络连接。
- `packages/orchestration/p2r_orchestration/report_builder.py`：当前证据等级与 not_comparable 报告。

## 3. 系统职责

### 3.1 Paper2Run 产品层

负责上传资料、编辑模型与目标配置、展示计划和过程、提供暂停/继续/停止入口、读取证据和导出报告。持久化任务目标、方案版本、配置快照、会话关联和运行记录。

不在业务后端再实现一套与 Harness 重复的模型推理循环，不逐条解释 SSH 命令含义来推进实验。

### 3.2 Harness 适配层

负责装配成熟 SDK、模型与工具、加载 Skills 和任务上下文、会话恢复、上下文管理、工具事件转换与用量记录。

逻辑接口至少覆盖：启动任务、追加用户指令、恢复会话、暂停调度、停止任务、订阅事件。具体 SDK 函数和消息格式在选型验证后确定。

Harness 的模型调用可使用用户配置的服务；工具调用、流式、上下文和恢复能力必须实测，不根据模型名称推断可用。

### 3.3 执行环境

本地和 SSH 目标都作为执行目标。Harness 使用工具连接目标并操作实验工作区。工具实现负责可靠执行、返回结果和保留句柄；Agent 决定下一步动作。

长期任务管理可以由 Harness 扩展加远程脚本或轻量服务实现，选最小可行方式。不得因为此前讨论过远程服务，就把自研常驻 Runner 定为必选架构。

### 3.4 事实与证据层

采集真实命令、退出状态、日志、代码快照、数据来源、依赖信息、checkpoint 和结果。保存失败与变更历史，避免重试覆盖证据。

模型可以提出结论，最终报告必须能区分模型判断、工具观测和评测计算。未建立比较依据时不生成“复现成功”结论。

## 4. 基础配置约定

以下是拟定配置格式，用来约定内容与权限边界，不代表已有读取实现。持久配置与当次会话配置分别管理；用户在界面修改后产生版本和任务快照。

```yaml
schema_version: paper2run.project.v1
project:
  id: example-project
  workspace: ./workspace
model:
  provider_profile: research-model
  credential_ref: credential-store:model-default
harness:
  adapter: selected-sdk
  skills:
    - paper-analysis
    - research-environment
    - experiment-debugging
    - result-audit
target:
  kind: ssh
  profile: rented-gpu
  ssh_config_alias: p2r-rented-gpu
  remote_workspace: /workspace/paper2run/example-project
  allocation: dedicated
  isolation: required
limits:
  wall_time_seconds: 14400
  max_model_calls: 200
  max_model_tokens: 1000000
  storage_bytes: 107374182400
  gpu_devices: ["0"]
network:
  public_internet: true
  host_and_metadata_access: false
experiment:
  objective: reproduce-selected-experiment
  protocol_change_policy: version_and_pause_if_outside_authorization
```

示例额度只是格式示例，不是默认配置。正式默认值需要根据验证任务制定。字段命名在接口冻结时统一。

配置解析器必须完成：

- 版本校验、字段校验和清晰的错误定位。
- 相对路径基于项目根解析；远程路径由 SSH 目标解释，不混用本地路径。
- `credential_ref` 和 SSH 别名由连接层解析，私钥、口令和模型 Key 不作为模型上下文内容。
- 区分“用户允许的资源”与“实际探测到的资源”；配置值不能充当 GPU 可用性证据。
- 配置快照记录目标、配额和能力包版本；敏感值不写入日志或导出。
- 不把配置中的墙钟时长等同平台费用。无平台计费接口时只显示估算或未知。

## 5. 工具与科研 Skills

### 5.1 基础工具

Harness 至少可用：文件读写与搜索、shell 执行、网络获取、代码版本检查、后台任务启动与查询、日志读取、任务停止、SSH 连接与文件同步、资源观测、产物登记。

短命令返回 stdout、stderr、退出码和耗时；长期操作返回稳定任务 ID，不占用一次模型调用等待训练结束。大日志按游标或范围读取，不能反复把全部日志塞进上下文。

SSH 工具读取基础配置并解析认证；Agent 获得连接结果与可用目标信息。不给模型私钥正文，不将 SSH agent 或管理凭据无条件转发到实验容器。

### 5.2 首版预装 Skills

| 能力包 | 必须说明的工作方法与输出 |
| --- | --- |
| 论文分析 | 原文依据、核心方法、实验条件、缺失项、候选目标 |
| 官方实现查找 | 仓库来源、版本、与论文关系、可访问性和授权条件 |
| 数据准备 | 数据出处、版本、划分、预处理、下载状态和校验 |
| 环境配置 | 现有环境探测、依赖安装、框架与 CUDA 验证 |
| 实验实现与调试 | 最小试跑、错误分析、修改记录、正式运行条件 |
| 长时间训练 | 后台任务、日志、checkpoint、重连、取消和清理 |
| 结果核验 | 指标计算、测试划分、泄漏风险、论文可比性 |
| 报告整理 | 运行事实、结论依据、偏差、失败和未完成事项 |

Skills 是按需加载的知识和流程，不强制拆成多 Agent。Prompt 分为全局原则、阶段指导、动态任务上下文和完成条件。预算和隔离通过工具执行，不依赖 Prompt 自觉遵守。

### 5.3 插件扩展

首版支持内置清单、版本、来源、启用/禁用、项目级选择和本地导入。带脚本或工具的插件应声明执行能力与依赖；安装不自动等于授予额外宿主权限。每次运行固定能力包快照，更新不改变正在运行任务。

后续商店可以复用同一清单格式扩展检索、分发和更新；首版不建设公开商店、支付或平台审核系统。

## 6. 自治、沙箱与资源边界

### 6.1 环境内开放

允许联网获取公开资料、克隆项目、下载合法可用的数据与权重、安装依赖、编译组件、修改代码、运行脚本、管理训练进程。专用隔离容器或虚拟机内可提供满足依赖安装所需的权限。

数据需要人工登录、许可接受或专用凭据时，任务记录阻塞原因并请求必要输入，不编造下载成功。

### 6.2 环境外保留边界

宿主目录、其他任务、平台管理凭据和控制面存储不属于 Agent 的实验权限。操作系统安装权限仅限已授权的专用实验环境；远端 SSH 登录为 root 不代表可以修改整台共享机器。

venv、conda、普通工作目录和 SSH 本身都不构成安全沙箱。远端必须探测隔离能力；无法满足时暂停并说明缺失条件，不静默降级为共享宿主上的无限 shell。

公网科研访问默认可开放；需要在真实网络层落实宿主、内网管理和云元数据边界，不能只写一条 Prompt。具体机制按隔离方案验证，包括重定向和代理路径。

### 6.3 资源与协议变更

Agent 在配额内调节 worker、checkpoint 频率等运行策略。任何可能影响结果的调整均记录。

减少数据、改变模型、缩减轮数、改变评测划分等产生新方案版本。是否继续由事先授权的变更范围决定；超范围时暂停请求用户决定。

时长、存储、模型调用与 GPU 分配分别记录。能够硬限制的额度由环境和工具落实；无法可靠限制的项目明确标为观测值或估算值。

## 7. SSH 与恢复语义

连接流程：读取目标配置 → 验证主机身份 → 连接 → 探测系统/GPU/存储/隔离 → 建立任务工作区 → 准备环境 → 执行与监控 → 回收产物。

首次未知主机指纹需建立可信记录；后续指纹变化必须停止连接并提示，不能自动关闭主机校验。

首版验收要求：

- 长期任务有独立于 SSH 连接的生命周期和稳定 ID。
- 状态与日志在远端保存；重连读取已有任务，不盲目重跑启动命令。
- 已提交但响应丢失的启动操作，可以通过启动标识对账。
- 停止覆盖本任务进程树，并给出最终停止状态；不影响其他用户任务。
- 远程执行端独立实施已接收的时限，本地断线不使时限失效。
- 远程重启或进程丢失后区分未知、已终止、可恢复；不假报运行中。
- checkpoint 恢复取决于代码支持及文件完整性，失败要如实报告。

必须区分三种情况：

1. SSH 断线而本地 Harness 仍在运行：重连后可继续观察和决策。
2. 本地软件关闭：已启动训练可以继续；Agent 自主决策暂停，重新打开后恢复会话。
3. 远程训练进程失败：恢复会话不等于恢复训练，需检查 checkpoint 或重新启动策略。

首版不承诺关机后 Agent 持续自主排错。不做平台释放，停止任务不等于停止实例计费。

## 8. 通用实验协议与评测

实验协议至少记录：研究问题、论文证据、输入数据、方法与参数、代码入口、环境要求、预期产物、评测规则、参考结果、允许偏差和预算。

分类准确率作为已有适配器保留，不再作为所有任务的强制输出。回归、生成、优化和仿真按需要接入评测适配器，不在首版承诺全部领域已支持。

通用原则：

- 区分探索性验证、缩减实验、原文协议尝试和可比较评测。
- 数据与划分有版本；代码与环境有快照；每次运行对应明确方案版本。
- Agent 可提出评测代码，但正式比较前冻结协议和评测版本。
- 正式评测运行与可修改实验代码隔离；不允许根据结果回改标准后沿用原评测身份。
- 有些科研任务需要读取标签，不能一律禁止；需按训练、验证、正式评测角色区分访问，并披露是否存在隐藏测试集和独立评测条件。
- 同一 Agent 生成数据、标签和预测时，重新算分不能证明科研有效性；报告必须披露来源。
- 保留 not_comparable 等诚实状态；缺乏正式比较证据时不能凭模型解释升级结论。

## 9. 用户流程

1. 上传论文及可选补充材料，完成文档解析。
2. 选择模型、预装能力包和本地/SSH 目标。
3. Harness 阅读资料、查找实现和数据，提出实验目标、缺失项与资源需求。
4. 用户确认目标、资源边界和允许的方案变更范围。
5. Harness 准备环境、实现或适配代码，完成小规模试跑。
6. 正式执行，在授权范围内调试和恢复；超范围或资料缺失时暂停。
7. 固定产物并执行评测，分析与论文的差异。
8. 生成报告并导出代码、环境、日志、配置安全投影与结果证据。

页面展示阶段可以有顺序，Agent 执行允许回退与循环。界面应显示当前目标、实际动作、修改原因、资源用量、待决定事项和失败原因，而不只显示模型聊天文本。

## 10. 分阶段工作计划

以下各阶段都是可单独验收的工作包。阶段 0 结束后，为选定 SDK 与执行方案编写逐文件实施计划；不得在未验证依赖接口前编造可运行代码计划。

### 阶段 0：验证 Harness 与执行基础

- [ ] 验证 Pi SDK 候选的版本、许可证、工具注册、事件、会话持久化、恢复、取消和模型兼容性；记录可复现证据。
- [ ] 以一个公开小项目验证：模型调用 shell、安装依赖、运行多文件程序并针对真实报错修复。
- [ ] 在用户提供的已租 SSH 目标验证真实连接、GPU、隔离、后台任务和重连能力；未获得目标前仅完成本地验证并标明远程未验证。
- [ ] 比较 SDK 原有 SSH 能力与轻量扩展，选择能满足任务标识、日志和取消要求的最小方案。
- [ ] 锁定依赖、配置字段、事件协议和恢复语义，输出各子系统实施计划。

交付：选型记录、最小验证材料、配置契约和任务拆分。验收：真实工具调用与恢复证据，不能只展示 SDK 示例启动成功。

### 阶段 1：配置驱动的自主实验闭环

- [ ] 实现配置版本校验、凭据引用解析和任务快照。
- [ ] 集成 Harness 会话、事件桥接和模型用量记录。
- [ ] 提供工作区、shell、网络获取和后台任务工具。
- [ ] 预装科研 Skills，支持能力清单及按需加载。
- [ ] 使用真实数据完成一个小实验，保留依赖安装、代码修改、试跑和结果。

交付：本地隔离环境中的自主实验闭环。验收：从真实失败恢复、可取消、记录可回查；不依赖固定标准库脚本。

### 阶段 2：已有 SSH 算力接入

- [ ] 界面生成目标配置，Harness 使用认证引用连接目标。
- [ ] 实现主机身份校验、环境探测和隔离检查。
- [ ] 实现长期任务标识、远端日志、进程树停止和时限。
- [ ] 实现断线重连、启动响应丢失后的对账和产物同步。
- [ ] 验证本地应用关闭后训练继续，重新打开后恢复会话和监控。

交付：用户已租 GPU 机器上的真实实验。验收：断线不重复训练、取消不误杀、没有隔离就不宣称受控执行；明确平台仍可能计费。

### 阶段 3：证据、评测与界面迁移

- [ ] 引入通用实验协议与方案变更记录，保留旧实验可读取性。
- [ ] 扩展产物与评测接口，保留准确率适配器并加入一种非分类实验验证通用性。
- [ ] 实现正式评测冻结与不可比状态处理。
- [ ] 展示工具活动、任务进度、资源、暂停原因和恢复入口。

迁移原则：

- 新路径先作为自主实验模式接入，旧模式保留回归用途和历史记录读取。
- 不直接删除旧安全白名单，让新隔离执行路径使用自己的能力策略。
- 旧报告保留原证据类别，不追溯升级为新能力结果。
- 新配置与任务明确版本；失败回退不静默切换成合成数据或固定报告。
- 现有数据库迁移、桌面打包和启动路径都纳入发布检查。

## 12. 必测失败场景

| 场景 | 预期行为 |
| --- | --- |
| SSH 认证失败或主机指纹变化 | 停止连接，显示具体原因，不刷屏重试或绕过校验 |
| 安装依赖失败、CUDA 不兼容 | 保存证据，在预算内修复；无法解决则报告阻塞 |
| 下载中断或数据无访问权 | 不标记完成；可恢复下载或请求输入 |
| 启动成功但响应丢失 | 按启动标识对账，不重复创建训练 |
| 本地断网、应用退出 | 已启动任务按远端时限继续，重开后对账 |
| 远端重启、磁盘满、显存不足 | 明确失败状态，检查 checkpoint，保留原因和调整 |
| 用户停止、预算耗尽 | 停止相关调用与任务；确认无本任务遗留进程 |
| Agent 减小数据或更换模型 | 创建偏差/方案版本，不沿用原协议成功结论 |
| 插件更新、会话损坏 | 使用原能力快照，必要时派生新会话并保留旧记录 |
| 缺少独立评测或可信数据 | 展示局限，不给无依据的复现成功判定 |
