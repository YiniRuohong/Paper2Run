## 📋 通用协议

### 路径、编码与类型

- 公共 API 前缀 `/api/v1`；内部 Runner 前缀 `/internal/v1`，不得经公网反向代理转发。
- JSON UTF-8；时间 ISO 8601 UTC；页面自行转本地时区。ID 为不透明字符串，示例 `prj_demo01`，不能拿 ID 拼宿主路径。
- 金额用 `currency + amount_micros`，整数表示百万分之一货币单位；字节、毫秒、token 用非负整数。ratio/percent 区分单位，未知值为 `null`，不能用 `0` 代替未知。
- 写入 schema 禁止未知字段。列表上限默认 20、最大 100，使用 opaque `cursor`，稳定排序 `(created_at,id)`。非法 cursor 返回 400。
- API 主体最大 1 MiB；multipart PDF 单独限 25 MiB，原文最多 40 页；这些是初始产品配置，不是赛事规则。
- 常规写接口返回 201/200，异步工作返回 202 加 `operation_id`；不长时间挂住 HTTP 等待训练。

成功 envelope：

```json
{
  "data": {"id": "prj_demo01", "name": "CIFAR 残差实验"},
  "meta": {"request_id": "req_demo01"}
}
```

列表 envelope：

```json
{
  "data": [],
  "page": {"next_cursor": null, "has_more": false},
  "meta": {"request_id": "req_demo02"}
}
```

204 无 body。二进制下载和 SSE 不套 JSON envelope。响应同时带 `X-Request-ID`；客户端不能注入该值作为服务器日志身份。

### 错误定义

```json
{
  "error": {
    "code": "REVISION_NOT_CONFIRMED",
    "message": "当前实验协议尚未确认，无法启动运行。",
    "retryable": false,
    "details": {"revision_id": "rev_demo02"}
  },
  "meta": {"request_id": "req_demo03"}
}
```

| HTTP | code 示例 | 客户端处理 |
|---|---|---|
| 400 | `INVALID_CURSOR / INVALID_ARXIV_ID` | 修正输入 |
| 401 | `SESSION_REQUIRED / SESSION_EXPIRED` | 登录，保留表单 |
| 403 | `FORBIDDEN / CSRF_FAILED` | 不自动重试 |
| 404 | `RESOURCE_NOT_FOUND` | 返回项目页 |
| 409 | `REVISION_CONFLICT / RUN_ACTIVE` | 刷新服务端状态 |
| 409 | `REVISION_NOT_CONFIRMED / POLICY_CHANGED` | 重新确认 |
| 409 | `IDEMPOTENCY_CONFLICT / EVIDENCE_CHANGED` | 不复用旧请求 |
| 413 | `FILE_TOO_LARGE / PAYLOAD_TOO_LARGE` | 缩减文件 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 使用 PDF |
| 422 | `SPEC_INVALID / UNSUPPORTED_RECIPE` | 展示字段问题 |
| 422 | `BUDGET_EXCEEDS_POLICY / BUDGET_EXHAUSTED` | 调整规模或人工处理 |
| 429 | `RATE_LIMITED / DAILY_QUOTA_EXCEEDED` | 尊重 Retry-After |
| 503 | `RUNNER_UNAVAILABLE / MODEL_UNAVAILABLE` | 明确可重试范围 |
| 500 | `INTERNAL_ERROR` | 展示 request_id |

跨项目资源对未授权用户返回 404，避免泄漏存在性；已知项目内不允许的操作返回 403。外部模型 raw error 不直接透传，避免泄露凭据或内部地址。

`details.field_errors` 为 `{path,code,message}[]`，前端按 JSON pointer 路径定位字段；不能用服务端报错字符串解析业务逻辑。

### 幂等和并发

创建项目、paper、experiment、revision、confirmation、run、export、删除项目要求 `Idempotency-Key`，使用客户端随机 UUID。取消天然幂等，仍允许该头。键作用域是 user + method + 规范 path，服务端保存 body fingerprint 与原响应至少 24 小时。

相同 key/body 返回同资源与原状态码，附 `Idempotency-Replayed: true`；相同 key 不同 body 返回 409。multipart fingerprint 使用文件内容 SHA-256 加受控元数据，不按随机 boundary 字节计算。重放前重新校验当前用户权限，项目删除/撤权后不能取回旧成功 body。并发相同 key 由数据库唯一约束和短事务占位去重；尚未完成的请求返回 409 `IDEMPOTENCY_IN_PROGRESS` 与 Retry-After，不能再次执行副作用。下载和 GET 不用幂等键。

保存 revision 使用 `base_revision_id` 乐观并发；新实验首次保存为 null。确认以 spec_hash、当前 head 和 policy_hash 做条件判断；先读后确认期间有变化返回 409，不偷偷确认新版。

## 🔐 会话、权限与能力目录

### 邀请登录

首版采用管理员为成员/评委配置账户和高强度一次性邀请凭据，不自建邮件发送平台、社交登录或公开注册。邀请凭据是敏感登录数据，通过人工私下渠道发给授权人，不能做公开固定“演示密码”。

`POST /api/v1/auth/session`，无需已有会话：

```json
{"invite_token": "<本人收到的一次性邀请凭据>"}
```

成功 201 设置 opaque `p2r_session` cookie：生产 `Secure; HttpOnly; SameSite=Lax; Path=/`。数据库仅存 session hash。会话最长 12h、空闲 2h 为初始策略；邀请凭据消费后不能重放。登录是一次性兑换的特例，不提供通用幂等响应重放：如果响应丢失，客户端先用 `/auth/me` 判断浏览器是否已收到 cookie，未建立会话则由管理员撤销未知会话并重新签发邀请，不能只凭 Idempotency-Key 取回 session secret。

登录校验 Origin 与速率限制，返回 user、可访问项目角色和非秘密 `csrf_token`。后续所有 cookie 鉴权写请求带 `X-CSRF-Token`，服务端校验 Origin。开发 localhost 可明确关闭 cookie Secure，仅 dev 环境允许。

`GET /api/v1/auth/me` 返回 user、当前 session 期限、csrf_token；`DELETE /api/v1/auth/session` 注销并清 cookie，返回 204。没有公开注册和任意账户修改角色接口。

角色：`owner` 管理成员和删除；`editor` 上传、修改协议、运行、取消、导出；`viewer` 只读授权项目和下载已有产物。评委默认 viewer，不能发起收费任务。成员管理初版使用管理员 CLI，保留审计，不开放无限邀请。

### 能力和异步操作

`GET /api/v1/capabilities` 返回账户可以使用的 recipe/version、实验模式、上传限额、运行限额、数据集、实际已验证模型展示信息、`execution_backend`（`mock/local/remote`）和 `data_mode`（`live/replay/mock`）。不返回 Key、内网地址或绝对宿主路径。

`GET /api/v1/operations/{operation_id}`：

```json
{
  "data": {
    "id": "op_parse01",
    "kind": "paper_extract",
    "status": "running",
    "resource": {"type": "paper", "id": "pap_demo01"},
    "stage": "extracting_tables",
    "progress": {"completed_units": 3, "total_units": 8},
    "error": null
  },
  "meta": {"request_id": "req_demo04"}
}
```

无法准确估计时 progress 为 null，而不是假进度。operation 归属项目，需同样鉴权。初版 paper/导出轮询建议 2 秒后指数退避到 10 秒；后台标签页更慢，不用忙轮询。

## 📚 项目与论文接口

### 项目

`POST /projects` 请求 `{name:string(1..120), description?:string(0..2000)}`，返回 201 Project。`GET /projects?cursor=&limit=` 返回当前用户可见项目；`GET /projects/{id}` 返回详情、角色和最近任务摘要。

`PATCH /projects/{id}` 仅允许 name/description，带 `If-Match` 对应响应 ETag，冲突 409；不允许通过 patch 修改 owner。

`DELETE /projects/{id}` 仅 owner，返回 202 Operation。先标 `deleting` 拒绝新任务、取消活动执行、等待确认，再清理对象和关联数据；活动容器未停止不宣称已删除。默认软删除入口，按保留策略物理清理；界面明确备份的到期时间。

### 上传与 arXiv 导入

`POST /projects/{project_id}/papers` 支持两种 Content-Type：

**multipart/form-data：**

| 字段 | 类型 | 规则 |
|---|---|---|
| `file` | binary PDF | 必填，最多 25 MiB |
| `title_hint` | string | 可选，不覆盖原文标题 |
| `source_processing_consent` | boolean | 必须显式为 true |

**application/json：**

```json
{
  "source_type": "arxiv",
  "arxiv_id": "1512.03385v1",
  "source_processing_consent": true
}
```

支持标准现代/旧式 arXiv ID 及合法版本号，拒绝任意 URL；前端可从用户粘贴的已知 arxiv.org 链接提取 ID，但服务端再验证。未指定版本时解析并持久化实际版本，不把“latest”作为重放身份。

返回 202：

```json
{
  "data": {"paper_id": "pap_demo01", "operation_id": "op_parse01", "status": "uploaded"},
  "meta": {"request_id": "req_upload01"}
}
```

本请求创建 paper，后续 ingestion/parse 由 Worker 完成。PDF 校验、渲染均有页数/内存/时间限制；重定向及 DNS 校验在联网准备域处理。并发重复上传同文件可提示复用，但不同幂等键代表不同上传意图，不暗中跨项目合并权限。

### 原文和解析结果

- `GET /papers/{paper_id}`：paper_id、project_id、status、sha256、arxiv_version、page_count、error、processing_consent 记录。
- `GET /papers/{paper_id}/content`：授权 PDF 字节，支持受控 Range；不能提供可永久公开访问原文件的 URL。
- `GET /papers/{paper_id}/extraction`：200 返回当前 Extraction；未完成返回 202 + operation_id；失败返回 paper 状态与标准 error，不捏造空成功。

Extraction 示例：

```json
{
  "data": {
    "extraction_id": "ext_demo01",
    "paper_id": "pap_demo01",
    "schema_version": "1.0",
    "fields": {
      "task": {"value": "image_classification", "evidence_status": "supported", "source_refs": ["src_01"]},
      "dataset": {"value": "cifar10", "evidence_status": "supported", "source_refs": ["src_02"]},
      "optimizer": {"value": null, "evidence_status": "missing", "source_refs": []}
    },
    "candidate_experiments": [
      {"id": "cand_resnet20", "label": "CIFAR ResNet-20", "source_refs": ["src_02"], "execution_support": "requires_review"}
    ],
    "source_refs": [
      {"id": "src_01", "page": 7, "section": "4.2", "quote": "We conducted more studies on the CIFAR-10 dataset", "bbox": null},
      {"id": "src_02", "page": 7, "table": "6", "row": "ResNet 20", "quote": "ResNet 20 0.27M 8.75", "bbox": null}
    ],
    "warnings": ["关键参数需人工确认"]
  },
  "meta": {"request_id": "req_parse01"}
}
```

正式输出的所有 source_refs 必须能解析到同一 extraction 内实际存在的 source，并绑定论文文件 hash。bbox 未可靠提取时为 null，不能虚构位置。`evidence_status` 枚举 `supported/inferred/missing/conflicting`，不使用未经校准的概率。

重试解析：`POST /papers/{id}/extractions` 请求 `{reason:string}`，返回 202。仅在失败/主动重解析时新建 extraction 版本并扣解析预算；已有确认协议不被新 extraction 静默覆盖。

## ⚙️ 实验协议、确认和启动

### 创建实验

`POST /projects/{project_id}/experiments`：

```json
{
  "paper_id": "pap_demo01",
  "extraction_id": "ext_demo01",
  "candidate_experiment_id": "cand_resnet20",
  "recipe_id": "cv.cifar_classification",
  "recipe_version": "1.0.0"
}
```

返回 201 `{experiment_id,status:"draft",head_revision_id:null}`。paper/extraction/candidate 必须同项目且互相关联。候选不支持执行则可创建仅设计草稿，但确认启动时拒绝，并列出缺失支持。

`GET /experiments/{id}` 返回当前 head、确认状态、链路 run、修复计数、预算账本摘要；`GET /experiments/{id}/revisions` 返回版本列表；`GET /spec-revisions/{id}` 返回完整不可变 spec、hash、validation、comparison_precheck 和 confirmation 摘要，支持刷新恢复与历史版本只读比较。所有查询校验父项目权限，不因版本已确认就允许公开读取。

### 保存协议版本

保持上轮路径：`POST /projects/{project_id}/spec-revisions`。请求必含 experiment_id、base_revision_id、spec：

```json
{
  "experiment_id": "exp_demo01",
  "base_revision_id": null,
  "spec": {
    "schema_version": "1.0",
    "paper_id": "pap_demo01",
    "extraction_id": "ext_demo01",
    "candidate_experiment_id": "cand_resnet20",
    "recipe": {"id": "cv.cifar_classification", "version": "1.0.0"},
    "mode": "smoke",
    "method": {"family": "resnet", "variant": "cifar_resnet20", "must_include": ["identity_shortcut"]},
    "dataset": {"id": "cifar10", "version": "registry_version_1", "split_policy_id": "recipe_smoke_split", "train_subset_fraction": 0.05},
    "training": {"seed": 42, "batch_size": 128, "max_steps": 100, "optimizer": "sgd", "learning_rate": 0.1, "weight_decay": 0.0001},
    "targets": [{"id": "target_01", "metric": "top1_error", "unit": "percent", "direction": "lower", "reference_value": 8.75, "source_ref": "src_02", "statistic": "single_reported", "tolerance": 1.0, "weight": 1.0}],
    "budget": {"max_model_calls": 20, "max_tokens": 120000, "max_execution_seconds": 300, "max_artifact_bytes": 1073741824, "currency": "CNY", "max_cost_micros": 5000000},
    "assumptions": [],
    "user_changes": [{"path": "/training/max_steps", "reason": "先检查流程，不作原文结果复现"}]
  }
}
```

首版一个 ExperimentSpec 固定一个 seed。基准的多 seed 重复采用多个独立 experiment，预先登记 `benchmark_case_id` 与 seed，均受账户总预算约束；维护者的 benchmark 工具按完整运行清单汇总，不选择性保留最佳值。首版 UI 不额外实现跨实验统计平台，下载报告必须披露自己仅是哪一次 seed 的结果。

`reference` 模式 schema 必须另外提供有效 batch、训练上限的 steps/epochs 二选一（以及另一个字段的换算/终止语义）、学习率分段或其他调度、momentum、初始化、预处理、增强、验证/测试划分、checkpoint 选择规则和重复试验统计口径。可用 tagged union 扩展不同优化器；不能用“recipe 会补齐”隐藏关键默认。上例为缩减展示的 smoke 合约，调用前 recipe validator 仍要完整校验。

这里的 5 元上限是**格式示例**，不代表已估算可完成训练；未指定的原文训练调度等正式字段仍须由 recipe schema 补齐或明确 unknown。各 recipe 使用 discriminated schema，而不是允许任意嵌套 dict。

返回 201 SpecRevision：`id`、revision_no、spec_hash、spec、`validation.issues[]`、`comparison_precheck`、`budget_estimate`、policy_hash、created_at。预估无法可靠给出时 amount/duration 为 null，加原因。`comparison_precheck` 对上例必须是 not_comparable。

revision 可保存不完整草稿；`confirm` 才要求所有执行必需字段满足。schema 类型错误直接 422，不存脏数据；科研缺失作为 validation issue 留在合法草稿内。

### 确认与不可变性

`POST /spec-revisions/{revision_id}/confirm`：

```json
{
  "spec_hash": "<服务端返回的64位SHA-256>",
  "policy_hash": "<本次能力与策略版本hash>",
  "accepted_issue_codes": ["SMOKE_NOT_COMPARABLE"],
  "accept_budget": true
}
```

返回 201 `{confirmation_id,revision_id,spec_hash,confirmed_at,confirmed_by}`。服务端核对当前 head、必需字段、recipe、权限、预算上限和模型配置；blocking issue 不能通过放进 accepted_issue_codes 消除。accepted 列表只表示接受可披露的 warning。

确认后仍不可调用模型偷偷扩展协议。代码 planner 发现缺失必要语义时返回 `needs_revision`，不自己选择新数据集。另一人更新 head 后旧确认成为非当前确认，但历史签名不删除。

### 创建运行

`POST /projects/{project_id}/runs`：

```json
{
  "experiment_id": "exp_demo01",
  "spec_revision_id": "rev_demo01",
  "confirmation_id": "cnf_demo01",
  "parent_run_id": null
}
```

返回 202：

```json
{
  "data": {"run_id": "run_demo01", "status": "queued", "events_url": "/api/v1/runs/run_demo01/events", "last_event_seq": 1},
  "meta": {"request_id": "req_run01"}
}
```

原子检查：当前确认、项目额度、实验剩余预算、队列容量、一个实验最多一个非终态 run；同事务写 run/job/event。仅“创建运行”预留初始启动额度，昂贵阶段逐次预留，不能超卖剩余额度。

修改实验语义后，原 run 终止为 awaiting_revision；用户确认新 revision，使用该实验最近的 awaiting_revision run_id 作为 parent_run_id 新建派生 run。派生候选消耗 experiment 的下一个 repair_ordinal，修复 ordinal 与总预算均不重置。首次 run 才允许 parent_run_id=null；其他终态不允许原 experiment 中免费重新生成，主动重复运行需新 experiment，但仍受账户日上限。

### SSE 与重连

`GET /runs/{id}/events?after=17`，同源 cookie 鉴权，`Accept: text/event-stream`。首连用 snapshot.last_event_seq 作为 after；自动重连如带 Last-Event-ID，则优先使用该 header。二者都没有从 0 开始。

```text
id: 18
event: attempt.failed
data: {"schema_version":"1.0","run_id":"run_demo01","seq":18,"occurred_at":"2026-09-19T10:00:00Z","payload":{"attempt_id":"att_demo01","execution_id":"exe_demo01","error_code":"SHAPE_MISMATCH","log_artifact_id":"art_log01","retry_class":"repairable"}}

id: 19
event: stage.changed
data: {"schema_version":"1.0","run_id":"run_demo01","seq":19,"occurred_at":"2026-09-19T10:00:01Z","payload":{"from":"executing","to":"repairing","stage":"repair_propose","run_version":9}}
```

事件 seq 在 run 内连续递增且由事务分配，Runner 本地 event_no 不能直接充当 seq。客户端按 seq 去重；至少一次投递，不保证恰好一次。event 写入提交后才可发送。分配 seq 与快照更新使用同一 run 锁以免漏事件。

| event | 必需 payload |
|---|---|
| `stage.changed` | from、to、stage、run_version |
| `artifact.created` | artifact_id、kind、bytes、sha256 |
| `attempt.failed` | attempt_id、execution_id、error_code、retry_class |
| `patch.proposed` | from_attempt_id、new_attempt_id、patch_artifact_id |
| `budget.updated` | actual、reserved、remaining、unknown_charges |
| `metric.verified` | metric_result_id、evaluator_version |
| `run.terminal` | status、terminal_reason、report_status |
| `report.ready` | report_id、version、content_hash |
| `log.chunk` | execution_id、stream、offset、text、truncated |

心跳使用 `: heartbeat` 注释，不占 seq，建议每 15 秒。单事件 payload 最多 16 KiB，日志按行合批并限速，完整日志保存在私有 artifact。慢客户端可断开重连，不持有无限内存缓冲。

事件保留期至少覆盖 run 可访问期。若清理后 cursor 早于 earliest_seq，**流建立前返回 409 `EVENT_CURSOR_EXPIRED`**；页面改走 polling 检测并拉最新快照，不让原生 EventSource 无限重试。会话过期先关闭 SSE，走 `/auth/me` 检查后再登录；禁止用 query token 修补鉴权。

### 取消、代码和日志

`POST /runs/{id}/cancel` 请求 `{reason?:string(0..500)}`，活动任务返回 202 `{status:"cancel_requested"}`。已终态返回 200 原状态，绝不回退。被取消任务也生成诊断报告。

`GET /runs/{id}/attempts` 返回列表，每项含 attempt_index、repair_ordinal、code_manifest_id、error_summary、patch_artifact_id、前后 hash、时间。`GET /attempts/{id}/files` 返回文件路径/大小/hash 与可预览 artifact_id，不返回宿主目录。

`GET /artifacts/{id}/text?offset=&limit=`：仅允许已登记 text/plain 或可预览代码类型，offset 是字节偏移，UTF-8 边界由服务器对齐并返回 next_offset，单次最多 64 KiB。大日志分块读，不把几 MB 堆进 SSE。

生成代码预览不可执行，默认只读。MVP 不开放在线任意 terminal 和任意文件写接口；人工修改协议走新 revision，不修改运行中目录。

## 📊 报告、指标与导出

### 报告读取

`GET /runs/{id}/report`：准备中返回 202 operation_id；ready 返回 200：

```json
{
  "data": {
    "id": "rpt_demo01",
    "run_id": "run_demo01",
    "version": 1,
    "mode": "smoke",
    "data_mode": "live",
    "verdict": "not_comparable",
    "comparison_reasons": ["SMOKE_MODE", "TRAINING_BUDGET_REDUCED"],
    "score": {"policy_version": "heuristic-1", "metric_match": null, "process": 0.4, "environment": 0.6, "total": null},
    "metrics": [],
    "evidence": {"spec_revision_id": "rev_demo01", "manifest_artifact_id": "art_manifest01", "metric_result_id": null},
    "limitations": ["只验证流程，未完成原文训练预算"]
  },
  "meta": {"request_id": "req_report01"}
}
```

真实有预测时 metrics 记录 observed/ref/unit/delta_absolute/delta_relative/within_tolerance/comparable/evidence IDs；没有值时 null，不能将未测记录写为 0 或剔除。结构项分母固定，过程证据不完整就扣对应项。计算公式见总体架构，不能由前端另算一版。

`GET /runs/{id}/manifest` 返回固定 RunManifest：代码、数据、镜像、模型调用版本、所有 attempt/execution、seed/随机设置、GPU/driver、评测器、报告与产物清单 hash。若证据尚未完整冻结，返回 `status:"provisional"`，正式导出需 finalized。

### 异步导出

`POST /runs/{id}/exports`（editor/owner；viewer 只能下载已有导出）：

```json
{"formats": ["bundle_zip", "report_pdf", "report_markdown", "report_json"]}
```

返回 202 `{export_id,operation_id,status:"queued"}`。相同 manifest/report hash 与格式可复用已有导出。`GET /exports/{id}` 返回状态和每种格式的 artifact_id/error，PDF 失败不删除成功的 JSON/ZIP。

ZIP 只包含授权且 finalized 产物；可选大权重需显式 include_checkpoint 和大小预检；数据集和论文全文默认不打包。下载包的运行入口由维护者维护，并说明许可、网络准备和镜像 digest。

`GET /artifacts/{id}/download` 返回授权文件流，或 303 到最多 60 秒有效、单对象只读的签名 URL。只读签名 URL 在有效期内就是 bearer capability，应短期并用 `Cache-Control: private, no-store`；长期分享和跨用户授权不走此接口。

首版不提供匿名公共分享、`docker commit` 镜像下载和任意格式转换。用户可以下载固定 recipe 镜像引用与运行说明，避免把运行目录和私密数据打进镜像。

实验模型预算用尽时也必须可以获得失败证据：终态先由确定性程序生成最小 JSON/Markdown 报告，不依赖额外 Qwen 调用；语言解释是剩余预算内可选步骤。PDF/ZIP 用独立、有上限的导出作业资源，失败可单独重试。下载已有证据不再消耗模型额度，但仍受带宽和权限限制。

## 🖥️ Runner 内部协议

### 认证与领取

仅部署在私有接口，mTLS 验证 Runner 身份，登记 runner_id 与 allowed capability（recipe、device、image digests）。HTTP body 中的 runner_id 必须与证书映射一致，不能靠字段自报身份。证书轮换与吊销由管理员处理。

`POST /internal/v1/runners/{runner_id}/leases:claim` 请求：

```json
{"capabilities": {"device": "cuda", "slots_total": 1}, "known_execution_ids": []}
```

API 取“注册能力与当前报告能力”的交集，不能通过自报新增权限。无任务 204；有任务 200，返回 lease_token、execution descriptor、下载能力与签名。领取默认短轮询 2 秒并加抖动，不让连接占用数据库事务。

```json
{
  "execution_id": "exe_demo01",
  "attempt_id": "att_demo01",
  "lease_epoch": 3,
  "phase": "smoke_execute",
  "recipe": {"id": "cv.cifar_classification", "version": "1.0.0"},
  "image_digest": "sha256:<64位镜像摘要>",
  "inputs": [{"artifact_id": "art_code01", "sha256": "<64位摘要>", "mount_role": "code_ro"}],
  "limits": {"cpu_millicores": 4000, "memory_bytes": 8589934592, "pids": 128, "wall_time_seconds": 300, "output_bytes": 1073741824},
  "issued_at": "2026-09-19T10:00:00Z",
  "expires_at": "2026-09-19T10:01:00Z",
  "policy_hash": "<64位策略摘要>"
}
```

descriptor 明确不含任意 argv、shell、docker flags、宿主挂载路径、密钥或动态镜像 tag。Runner 按 recipe+phase 映射固定命令。示例尖括号是占位符，不是合法实际 digest。

签名设计：API 对固定 canonical JSON descriptor 生成 Ed25519 签名，附 key_id/signature，Runner 只信任预分发公钥；下载 URL 独立短期更新，但内容必须匹配签名 inputs hash。签名有效期检查适用于初次接纳，运行有效性由持续租约心跳维持。已接纳相同 execution_id/epoch/hash 幂等返回已有句柄；同 ID 不同 hash 直接冲突。

### 心跳、事件、完成和产物

- `POST /internal/v1/executions/{id}/heartbeat`：带 lease_token/epoch、本地 state、GPU/CPU/RAM、last_event_no；返回新租约截止、`cancel_requested` 和允许继续标志。旧 epoch 返回 409，Runner 停止该执行。
- `POST /internal/v1/executions/{id}/events`：发送 `{lease_epoch, events:[{event_no,type,time,payload}]}`；每批最多 100 条/256 KiB，event_no 在执行内唯一，服务端去重后再分配 run seq。无权直接发送 `metric.verified` 或 `report.ready`。
- `POST /internal/v1/executions/{id}/artifacts:init`：登记 allowlist 中的 logical_name、bytes、sha256、media_type；校验额度后返回 staged artifact ID 和限定上传能力。
- `POST /internal/v1/executions/{id}/complete`：请求包含 lease_epoch、exit_code、terminal_reason、产物列表、资源摘要及最后 event_no；完整性验证通过后记录完成并触发下一阶段。

Runner 只有在停止容器、冻结输出、验证文件类型/路径/大小后申请上传。API 完成接口校验对象存在、字节数和 checksum；不信任 Runner 自报值直接发布。清单 hash 对完成调用幂等；重复且一致返回原 ACK，不一致 409。lease_token 不写日志、不传给容器，终态后吊销。

首次完成必须属于当前有效租约；过期 Worker/Runner 的迟到产物进隔离诊断区，不覆盖正式证据。已成功提交后 ACK 丢失的同哈希重试可以读回原 ACK，无需再次训练。人工恢复不能绕过身份或 hash 校验。

### 无网络输入与输出流程

```mermaid

    accDescr: Runner pulls a signed job, downloads authorized inputs, starts an isolated container, uploads validated outputs, and completes the job before the trusted worker verifies metrics.

    participant box as 隔离容器
```

## ✅ 合约生成与验收

### 实现后的单一 schema 来源

后端 Pydantic 模型为 API schema 源，运行时导出 OpenAPI 3.1 到 `packages/contracts/openapi.json`；用 `openapi-typescript` 生成前端类型，以 `openapi-fetch` 消费。前端不能手写一套与 Python 不同的 Run/Metric 类型。

recipe schema、SSE payload、Runner descriptor 用同一 Pydantic 类型导出 JSON Schema 并版本化。领域内部类型可独立，但边界必须显式转换。合约变更需补示例、兼容性测试和版本说明。

本轮仅提供详细设计，不声称上述生成文件或工具已存在。落地后 `make contracts-check` 应导出并比较受控快照，存在破坏性差异则 CI 失败。

### 必须通过的接口测试

- 上传、确认、run 创建完整正向链；另覆盖未确认、过期确认、关联资源跨项目。
- 相同幂等请求只创建一次；同 key 不同 body 返回 409；两个并发启动只允许一个。
- SSE 快照交接无丢事件、重连可重放、重复事件去重、过期 cursor 可恢复。
- 旧租约不能完成任务，ACK 丢失可以对账，不重复启动 GPU。
- 取消与完成竞态最终只有一个一致终态，资源已回收才宣称取消。
- 预测覆盖检查、NaN 拒绝、fake metrics 不生效、不可比结果 total=null。
- 所有 artifact/operation/attempt/export 通过父项目做权限校验；仅知道 ID 无法下载。
- stdout、论文和 Qwen 响应中的恶意 HTML/命令不会执行；Key 不进入响应/导出。
