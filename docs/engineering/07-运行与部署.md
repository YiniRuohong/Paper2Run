## Phase 0/1 本地 Demo（已实现）

这是可接入真实前端的开发演示，不是生产部署。Demo 使用 SQLite、真实 FastAPI API、持久化 ArtifactStore 和受控本地 Python Kernel；本地 Kernel 不是 hostile-code sandbox，Checkpoint 只保存执行元数据，Restore 可能返回 `recovered`、`partial` 或 `failed`，不得据此宣称完整 Python 内存快照恢复。

在目标 worktree `/Users/andyzhao/Documents/claude code/Ali_Hackthon/.worktrees/phase0-phase1` 中运行：

```bash
uv sync
mkdir -p .p2r-demo-8010
P2R_DEMO_DIR=.p2r-demo-8010 uv run uvicorn p2r_api.main:create_demo_app --factory --host 127.0.0.1 --port 8010 > .p2r-demo-8010/server.log 2>&1
pnpm --dir apps/web install --frozen-lockfile
P2R_API_TARGET=http://127.0.0.1:8010 pnpm --dir apps/web dev --host 127.0.0.1 --port 5173
```

访问 `http://127.0.0.1:5173/lab`。Vite 仅代理浏览器业务请求 `/api/v1` 与健康检查 `/healthz`；前端不得直连数据库、ArtifactStore、Docker、Kernel、Worker 或 `/internal/v1`。如 8000 已被占用，保持 Demo API 使用 8010，并设置 `P2R_API_TARGET=http://127.0.0.1:8010`。

Demo 工作台保留队友的四视图 Mock（默认入口），真实 Session/Cell/Events/Actions/Checkpoint/Restore 工作台独立位于 `/lab`；Mock 通过不代表真实 API 或执行链通过。当前 Demo 未实现论文解析、真实训练、Runner/Evaluator、Report、正式认证、生产沙箱、PostgreSQL、Docker、GPU 和完整产品链路。

已验证命令：

```bash
pnpm --dir apps/web test
pnpm --dir apps/web exec tsc --noEmit
pnpm --dir apps/web build
uv run pytest -q
uv run python -m compileall -q services packages tests
```

浏览器验收至少检查：`GET /healthz` 返回 `status=ok`；`/lab` 页面加载；Cell 写入使用 `Idempotency-Key` 并显示真实状态；Checkpoint 使用真实 namespace/environment/action cursor；Restore 明确显示服务端恢复分类和原因。写请求不自动重试，网络未知结果先刷新核对。生产能力和外部公开部署不由本 Demo 覆盖。

## ⚙️ 文档边界与运行前提

依据：[模块与数据](05-模块化与数据设计.md)、[接口定义](06-接口定义.md)、[总体架构](02-技术架构.md)、[阶段排期](03-实施计划与验收.md)；实施拆分见 [开发任务包](08-开发任务包.md)。发生设计缺口时交主 Agent 决策，不自行替换技术栈。

**本文分为两类内容：** 上方“Phase 0/1 本地 Demo”记录当前已实现、可运行并已验证的开发链路；其余章节记录生产级部署与未来能力的设计契约，除非另有明确标注，不应视为本 Demo 已实现。本轮不调用收费模型、不购买资源、不发布部署。

- 固定选型：React + TypeScript + Vite；建议 Python 锁定 3.11 为基础；FastAPI + Pydantic 2；PostgreSQL + SQLAlchemy 2 + Alembic。
- API 是模块化单体；Worker 为独立进程，PostgreSQL 同时保存业务状态和持久任务队列；不引入 Redis、Celery、LangGraph 或 Kubernetes。等待确认属于 Experiment，不预建 waiting_confirmation Run。
- Runner 为独立执行进程，经私网 mTLS 主动领取签名 execution；控制面不挂 Docker socket，不在 API/Worker 内执行生成代码。
- Node、pnpm、uv、数据库及镜像版本需在首次兼容测试后精确锁定；不能将“版本建议”写成“兼容性已验证”。
- 只面向邀请成员与已审查 recipe；容器并不构成完全防逃逸保证，隔离测试失败时禁止开放上传执行。

## ⚙️ 四种运行模式

运行模式与实验协议中的 `smoke/scaled/reference` 是两组不同字段，不互相替代。

| 运行模式 | 拟启动单元与依赖 | 可做什么 | 必须披露的限制 |
|---|---|---|---|
| `mock-ui` | Web 与浏览器测试 fixture；不启动 API、Worker、Runner、数据库或容器 | 页面、错误态、交互测试；能力返回 `mock/mock` | 无模型调用、无训练；页面常驻“测试数据”，不得作为真实结果 |
| `local-cpu` | 本机 Web/API/Worker/PostgreSQL、独立 CPU Runner；需 Docker 与匹配 CPU 架构的受控镜像 | 可信本机开发者在隔离容器做真实 `smoke`；能力返回 `local/live` | 无 CUDA，不开放他人上传执行，不支持全量训练承诺 |
| `remote-gpu` | 开发或部署控制面，加专用 Linux NVIDIA Runner；私网 mTLS | 经预检授权后执行支持的实验模式；能力返回 `remote/live` | GPU、Qwen、镜像和数据均须先验证；未通过就禁止收费阶段 |
| `replay` | Web 与只读历史查询 API；使用已授权真实历史数据库/产物副本，无 Worker/Runner | 浏览历史日志、代码、报告，下载已有导出 | 全程显著“历史回放”；不生成新 run、报告、导出，不伪造实时进度 |

能力表的成对值依次为 `execution_backend/data_mode`。replay 保留来源的 `local` 或 `remote` backend，展示层标 `data_mode=replay`，不改写历史 RunManifest。没有真实历史记录时展示空态，不用 mock 冒充回放。

ARM Mac 可开发 Web/API/Worker；本机 CPU smoke 仍需通过镜像架构兼容性检查。Mac Docker 不提供本方案所需 CUDA，不能把 CPU 结果宣称为 Linux GPU 结果；不支持的架构应明确阻断而非默认模拟成功。

## ⚙️ 服务、端口与网络职责

下表地址属于生产设计契约；Phase 0/1 Demo 的实际 API 端口为 `127.0.0.1:8010`，Web 为 `127.0.0.1:5173`，详见本文开头。

| 单元 | 开发监听/访问约定 | 生产约定 |
|---|---|---|
| Web | `127.0.0.1:5173`；固定使用同一浏览器 origin | 构建静态资源，由 HTTPS 同域入口提供，不暴露 Vite 开发服务 |
| API | `127.0.0.1:8000`；Web 代理公共 `/api/v1` | 仅回环/内网；公网反向代理仅转发公共接口 |
| PostgreSQL | `5432` 仅回环或私有网络 | 仅控制面私网允许列表；浏览器和 Runner 无访问权 |
| Worker | 无业务监听端口；通过 repository/UnitOfWork 访问 DB | 独立进程；持有必要模型凭据，不持有 Runner 容器执行入口 |
| Runner | 不监听公网；主动连内部 API 和限定对象传输入口 | 私网 mTLS；本地健康检查限回环或本地管理通道 |
| 内部 API | `/internal/v1` 由独立入口 `127.0.0.1:8443` 提供 mTLS | `INTERNAL_API_BIND` 指定私网 IP:8443，仅 Runner 网段可达 |
| 对象存储 | ArtifactStore 本地实现，按授权接口传输文件 | 私有 OSS；限定对象、短期读写能力，无公开 bucket |

生产公网仅开放经授权的 HTTPS 入口 `443`；管理入口限管理网络。Runner 不能直达数据库、云元数据或其他内网服务，容器更不能继承宿主网络权限。

API 使用同一代码仓库的两份应用装配：public app 在 8000 只注册 `/api/v1`，internal app 在 8443 只注册 `/internal/v1` 且强制客户端证书。不能只在公共代理隐藏路径、却让 8000 上的 internal route 无认证可达。mTLS 可在同机可信反向代理终止，后端仅通过回环/Unix socket 接收由该代理重写的证书身份；禁止信任客户端自带身份头。local-cpu 的 `make dev` 同时装配受限 internal 入口，mock-ui/replay 不启动它。

## ⚙️ 生产设计命令与精确职责

**本节命令属于未来生产契约，不是当前 Demo 的启动入口。** 依赖运行环境的目标必须用 `MODE` 选择四模式，不提供隐式 live 默认值；unit/contracts 不依赖运行模式。`TASK=T01` 至 `T10` 仅筛选开发任务测试，不赋予外部资源使用权。

| 命令 | 必须实现的职责 | 不得隐式做的事 |
|---|---|---|
| `make bootstrap MODE=local-cpu` | 检查工具链版本，按冻结锁安装项目隔离依赖，准备非秘密本地配置 | 不升级锁、不安装系统驱动、不申请云资源、不启动服务；缺锁即失败 |
| `make infra-up MODE=local-cpu` | 在授权本地环境启动专用 PostgreSQL，准备私有本地存储目录 | 不迁移、不清空库、不启动 Runner；mock-ui/replay 不自动拉起写入基础设施 |
| `make migrate MODE=local-cpu` | 检查目标库身份和迁移版本，执行已审阅 Alembic 升级 | 不自动降级、不重置库、不修改历史证据；生产要求备份与批准 |
| `make dev MODE=local-cpu` | 启动 Web/API 及同源代理；mock-ui 仅 Web；replay 仅只读查询组合 | 不自动启动 Worker/Runner，不开启收费阶段 |
| `make worker MODE=local-cpu` | 独立领取 DB jobs，续租、阶段提交、预算预留和恢复对账 | 不执行生成代码；mock-ui/replay 必须拒绝启动 |
| `make runner MODE=local-cpu` | 在已批准宿主监管下分别启动 Runner 主循环与独立 reaper，核验身份/能力后领租约并执行固定 recipe+phase | 不接受任意 shell/argv，不持有 Qwen Key；mock-ui/replay 拒绝启动，不自动修改系统监管配置 |
| `make doctor MODE=local-cpu CHECK=preflight` | 仅本地只读检查：工具链、配置完整性、端口占用、架构和权限 | 不安装、不连接收费模型、不创建任务 |
| `make doctor MODE=local-cpu CHECK=ready` | 检查已启动依赖、迁移 head、授权存储、Runner 心跳和能力 | 不训练、不试探收费 API；真实模型探测另需批准 |
| `make test-unit TASK=T01` | 运行所选 Python/Vitest 单测及对应静态检查 | 不连模型、外部服务或 Docker，不替换生产配置 |
| `make test-integration TASK=T03 MODE=local-cpu` | 在专用临时库/产物域测事务、租约、Runner 和失败路径 | 不使用真实项目库；容器测试需已批准 Docker 环境，缺条件明确失败/跳过 |
| `make test-e2e TASK=T08 MODE=mock-ui` | Playwright 四视图测试；live/replay 模式按授权测试环境接入 | mock 通过不能记成真实链路通过；不得自动申请 GPU |
| `make contracts-check` | 从 Pydantic 导出 OpenAPI 3.1/JSON Schema，临时生成 TS 并比较受控快照 | 不自动接受差异，不手改生成物消除错误 |

静态检查的具体工具版本随 T01 锁定；检查不得悄悄格式化覆盖文件。格式化仅在已授权任务目录执行。测试筛选的目录和 fixture 由任务包规定，未选中或跳过项必须列明。

管理员入口仍是未来生产契约：`uv run python -m p2r_api.admin invite-create` 创建受控账户与一次性邀请；`uv run python -m p2r_api.admin member-set` 设置已有项目成员角色。使用交互确认，不把邀请凭据放命令参数、公共输出或日志；必须记录不含秘密的审计。

## ⚙️ 首次启动顺序与真实资源前置

下列步骤中的命令沿用上节生产设计契约；只在代码实现、依赖锁及操作者授权具备后执行。

1. 选择模式，确认论文外传同意、数据许可和本次费用上限；先运行 `make doctor MODE=local-cpu CHECK=preflight`，缺工具只报告，不自动改系统。
2. 经批准准备锁定版本的工具链，再运行 `make bootstrap MODE=local-cpu`；不能通过删锁解决安装失败。
3. 准备私有配置与必要凭据；运行 `make infra-up MODE=local-cpu`，确认目标是开发专用库而非历史库。
4. 首次建库运行 `make migrate MODE=local-cpu`；已有库先备份并检查迁移兼容性，失败不继续启动任务消费者。
5. 管理员建立成员/评委一次性邀请；已有项目按 CLI 配角色，新项目 creator 为 owner。评委默认 viewer，不使用固定公开演示密码。
6. 运行 `make dev MODE=local-cpu`，核验登录、能力目录和内部 mTLS 入口；注册 Runner 身份、允许镜像 digest 与设备能力。
7. 前置检查通过后启动独立 `make worker MODE=local-cpu` 与 `make runner MODE=local-cpu`；先验证独立 reaper 已受监管、主循环退出仍能清理，再做 ready 检查；此前不接受收费 job。
8. 用维护者小型 fixture 检查训练、预测、独立评测及取消；经授权再使用真实 Qwen，之后才尝试新论文端到端流程。
9. `remote-gpu` 将控制面命令的模式显式改为该值，Runner 命令只在专用 Linux 主机执行；不能在控制面补挂 Docker socket 绕过失败。
10. `mock-ui` 只需预检、锁定依赖和 Web 测试；`replay` 只装载经核验历史副本及受限会话配置，跳过历史库迁移、Worker、Runner 和所有新任务步骤。

### 真实 Qwen 与 GPU 门禁

- 账户操作者核验 Qwen 地域、endpoint、API ID、额度和必要文本/图像能力；小额探测另行批准，登记实际用量与失败，不在 doctor 默认行为中收费。
- 真正 live 的解析/生成链不能用替身填补模型失败；缺权限返回可解释错误。有限网络重试消耗预算，鉴权失败不无限重试。
- GPU 前置为独立 Linux NVIDIA 主机、匹配 driver/runtime/PyTorch 的固定镜像 digest、数据及 split hash；先运行维护者代码验证环境，再允许生成代码。
- 单 GPU 单执行槽起步；CPU/RAM/pids/墙钟及输出额度均启用。显存观测不是硬配额保证，OOM 留诊断而非自动改实验语义。
- 模型 Secret 仅 Worker 持有；API 签名私钥和 Runner mTLS 私钥分别分发。Runner 不持有任何 DB 凭据或服务端对象存储凭据，只用限定对象短期传输能力；容器不获得上述凭据或传输能力。

## ⚙️ 同域代理、SSE 与邀请权限

本节接口路径属于生产设计契约；Demo 当前实现的公共接口见 [接口定义](06-接口定义.md) 和前端 API client，以实际代码为准，不新增公共管理接口。

- 开发 Vite 将同源 `/api/v1` 转到回环 API；生产 Web 与公共 API 共用 HTTPS origin，禁止泛化跨域放行。内部 `/internal/v1` 不由该代理公开。
- SSE 代理关闭响应缓冲/缓存，流式刷新；超时配置需容纳建议每 15 秒的注释心跳。上线前验证代理不会攒批日志才发送。
- 首取 run 快照，再用 `last_event_seq` 作为 `after`；重连 `Last-Event-ID` 优先，按 seq 去重。16 KiB 单事件上限与日志节流遵守接口契约。
- cursor 过期在建流前返回 409 `EVENT_CURSOR_EXPIRED`；客户端关闭原生重连，转轮询并取新快照。401/会话失效先检查会话再登录，不在 URL 放 token。
- `p2r_session` 生产启用 Secure/HttpOnly/SameSite=Lax；会话最长 12h/空闲 2h 为初始策略。登录校验 Origin 与速率限制，后续 cookie 写请求另校验 `X-CSRF-Token`。
- 登录是一次性兑换特例，不缓存/重放含 session secret 的响应；响应丢失先访问 `/api/v1/auth/me`，未建立会话则管理员撤销未知会话并重发邀请，不能凭 Idempotency-Key 取回 secret。
- owner/editor/viewer 权限逐资源回查父项目；跨项目 404、项目内禁用操作 403。replay 另外拒绝业务写操作，viewer 只能下载已生成产物。

## ⚙️ 执行目录、产物与日志协议

下列容器逻辑路径及文件名属于生产设计契约；不是用户可传入的宿主路径。

| 逻辑目录 | 挂载与用途 | 不得包含 |
|---|---|---|
| `code_ro/` | 本次候选代码及固定适配配置，只读 | 管理凭据、任意宿主目录、可写共享代码 |
| `train_data/` | 训练阶段只读；仅训练与协议允许的验证数据 | 受保护评测标签、预测阶段不需要的数据 |
| `prediction_inputs/` | 预测阶段只读；样本输入及稳定 sample_id | 标签、评测答案、指标程序 |
| `work/` | 本 execution 独立的有界临时工作区，可写 | 跨 run 共享缓存、其他用户文件 |
| `outputs/` | 本 execution 独立的限额输出区，可写，停止后冻结 | 任意宿主链接、设备文件、白名单外产物 |

Runner 根据 recipe+phase 固定挂载，不将 train_data 与预测标签混装；可信评测器在 Worker 域读取受保护标签。容器非 root、断网、只读 rootfs、去 capabilities、禁止提权，配置 seccomp/pids/CPU/RAM/tmpfs/墙钟限额；不使用 privileged、host network/PID 或 Docker socket。

- 日志拟保存为限额 JSONL：每行一个对象，至少有 schema_version、execution_id、event_no、time、stream、offset、text、truncated；Runner 赋身份并转义不可信文本。
- Runner event_no 只在 execution 内编号，由 API 去重后分配 run seq；完整日志进私有 artifact，SSE 仅放限长片段。不记录 lease_token、签名 URL、Key 或论文全文秘密。
- 权重拟采用仅权重 `weights.safetensors`，由 recipe 锁定 tensor 名称/shape/dtype；不能在控制面加载任意 pickle，生成模型的加载只能发生于隔离箱。
- 预测拟采用 `predictions.jsonl`，schema 由 recipe 版本固定为 sample_id 与 logits 或 prediction 的一个明确分支；限制行长、总字节、类别维度，拒绝 NaN/Inf、重复/缺漏/额外 ID。
- 固定评测器不 import 生成代码，只解析数据；最终 `metrics.json` 由其写出并绑定预测/标签/评测器 hash，生成代码同名文件和 stdout 数字均无权作为最终指标。
- 停止容器后检查路径、软链接、文件类型、大小及 checksum，再上传 staging；API 验证对象后 finalize。迟到旧租约产物只能进入隔离诊断，不能覆盖正式证据。
- execution descriptor 使用 canonical JSON + Ed25519 签名，核验 key_id/有效期/epoch/输入 hash；只接受固定 phase、资源策略、digest，不接受任意 argv 或动态镜像 tag。
- 同 execution_id/epoch/hash 幂等使用已有句柄；ACK 丢失先对账，旧 epoch 拒绝写回。取消需确认容器退出后才能释放槽位，不能按页面点击即宣称停止计费。
- execution 墙钟超时与租约 watchdog 必须独立于 Runner 主循环：Linux 宿主可用 systemd 监管独立 reaper，按受控容器标签、execution_id、epoch、租约 TTL 和墙钟截止清理，不只靠主循环定时器。
- 本机 CPU 模式使用相应宿主监管独立 reaper，不假设 Mac 有 systemd；运行进程不可延长自身租约或覆盖监管记录。杀死 Runner 主循环/中断心跳后，reaper 仍应在租约加宽限内停止相关容器，随后对账槽位；监管失效时拒绝新 execution。

## ⚙️ 两机生产部署、备份与回滚

以下部署路径和操作属于未来生产设计契约；没有云账户、域名、预算或访问授权时只准备模板，不实际部署。

1. **控制面主机：** HTTPS 反向代理、静态 Web、API、独立 Worker；PostgreSQL 可同机私网起步。使用最小权限 OS/DB 身份，无 Docker socket 挂载给应用，无生成代码执行。
2. **专用 Runner 主机：** Linux NVIDIA、受控容器运行时和 Runner，systemd 独立监管主循环与 reaper；只允许必要私网出站。镜像/数据在可信准备阶段获得并校验，执行容器全程断网。
3. **证据存储：** 私有 OSS，API 授权文件流或最多 60 秒单对象只读签名 URL；响应 private/no-store，下载能力不是永久分享授权。
4. **发布前：** 冻结代码、依赖锁、迁移版本、recipe/镜像 digest、schema 和 prompt；先测试环境过门禁，再经管理员批准切换 HTTPS 入口。
5. **备份：** 管理员确定备份频率、保留期和恢复目标；同时保存 DB 一致性备份、finalized 对象及清单版本，Secret/证书单独受限保管，不打入下载包。
6. **恢复演练：** 在隔离环境恢复 DB 与对象，核对 manifest hash、权限和下载；默认不启动 Worker/Runner，先对账 execution，避免恢复旧库后重复训练或复活已撤销授权。
7. **回滚：** 暂停新任务准入，等待/确认停止活动执行，保存证据；仅在 schema 向后兼容时切回上一固定应用版本。破坏性迁移不盲目 downgrade，需批准的恢复方案。
8. **观测：** 关联 request_id/run_id/attempt_id/execution_id，检查队列等待、租约超期、OOM、模型失败、预算未知项和 artifact 异常；指标缺失写 null，不显示伪零。

原 PDF/日志/模型调用摘要 7 天、固定报告/代码包 30 天是待批准的保留建议，不是已部署策略；run 事件至少覆盖 run 可访问期。项目删除先确认停止再清理，备份到期另行披露；恢复时应用删除/禁用记录，不能把旧备份直接开放。

## ⚙️ 故障排查与离线历史回放

### 排查顺序

仅使用前述未来生产设计的 doctor/查询入口和脱敏日志，不要求操作者粘贴 Key；当前 Demo 的排障以本文开头的进程日志、`/healthz` 和测试命令为准。

| 现象 | 优先证据 | 拟采取动作与边界 |
|---|---|---|
| API 启动失败或任务不动 | DB 目标、迁移 head、Worker 租约 | 修正配置/迁移；不删库，不把任务挪到 API BackgroundTasks |
| Qwen 401/403/429 | 脱敏 request_id、地域、模型 ID、账本 | 权限错误人工处理；429 有界退避，不换未批准模型绕过额度 |
| Runner 无任务 | 注册能力交集、证书、私网连接、队列 | 核对 device/recipe/digest；不把内部接口开公网 |
| GPU 不可用/OOM | 架构、driver、镜像、显存观测、退出码 | Mac 切 CPU smoke 或用已授权 Linux；语义变更重新确认 |
| SSE 卡住或重连风暴 | 代理缓冲、心跳、401/409、最新 seq | 禁缓冲，恢复快照/会话；不在 URL 添加 token |
| 取消后仍占槽/Runner 主循环退出 | 宿主监管/reaper、标签与租约 TTL、容器句柄、stop ACK | 显示停止确认中；独立回收后对账，不因 Runner 崩溃放任 GPU 继续运行或立即重发 execution |
| hash 不符或下载 404 | 权限、finalized 状态、对象 checksum | 拒绝发布损坏对象；未授权 404 不泄漏存在性 |
| 指标缺失或预测被拒 | ID 覆盖、有限值、schema/evaluator 版本 | 留真实诊断，不用训练日志补数；报告失败不改写 run 历史 |

### 离线副本与重新执行不同

1. 历史回放仅使用已经真实发生、允许展示的 run；包内保留原始时间、模式、终态、代码/数据/镜像/预测/报告 hash 与版本，不生成“现在正在训练”的时间线。
2. 导出默认不包含论文全文、数据集或大权重；逐项核对授权和再分发许可。无分发权时只给合法获取说明，缺文件就披露不完整，不能称离线可重跑。
3. 导入只读副本前核对可信来源的 manifest 及 `SHA256SUMS`，拒绝路径穿越、软链接和超限归档；hash 一致只证明内容一致，不替代来源或许可核验。
4. 离线查看不得回源拉私有数据、调用 Qwen、启动容器或创建新 export；本地提供受限邀请会话或管理员批准的只读展示范围，仍不开放匿名私密数据。
5. 若要在干净环境重新执行，那是另行授权的新执行：需兼容 CPU/GPU、固定镜像、数据/split hash、维护者入口及额度，重新记录 run 与真实成本；不能混入 replay 展示成绩。

## ⚙️ 成本估算与可配置护栏

以下是规划公式，不是实测价格、采购建议或自动消费授权。价格由操作者按已核验日期、地域、币种和计费口径填写；未知费用保留 unknown/reservation，不记为零。

```text
C_model = Σ[(input_tokens / 10^6) × P_input + (output_tokens / 10^6) × P_output]
C_gpu   = billed_gpu_hours × P_gpu_hour
C_store = stored_GB_month × P_storage + egress_GB × P_egress + request_fees
C_total = C_model + C_gpu + C_store + C_control
```

GPU billed hours 应按实际资源账单口径，可能包含空闲占用；`C_control` 为控制面资源分摊，账单未拆分时不得与 GPU 成本重复计入。取消 execution 不等于停止整台云主机计费。预算以整数 amount_micros 和币种传输，数据库 numeric 保存；不用浮点结算。

- 初始可配置护栏沿用设计：25 MiB/40 页上传、每 GPU 1 槽、用户最多 2 个排队任务、实验链最多 5 次代码修复；同输入同阶段基础设施重试最多 2 次。
- smoke 执行上限建议 300 秒；每 experiment 链初始 20 次模型调用、120k token，每 run 1 GiB 产物并受实验/账户总量限制；scaled/reference 时长显式确认，local-cpu 只开放 smoke。
- paper 上传解析单走 project/account 解析额度；生成/修复受 experiment 总预算和不超过其余额的 run 子上限约束。派生 run 不重置费用或 repair_ordinal，新建 experiment 也不能绕过账户日上限。
- 多 seed 基准为多个 experiment，每份 spec 固定单个 seed；预登记到离线 ledger，全部受账户总预算约束。不新增跨实验统计 UI，也不在原 revision 中替换 seed。
- Worker 心跳/租约建议 10/60 秒，Runner 5/30 秒、停止宽限最多 10 秒；统一策略配置并通过故障测试校准，不能独立调到互相冲突。
- 每次昂贵阶段前原子预留最坏可估费用，结束后结算；余额不足拒绝新增操作。没有可用单价或实际用量时展示估算依据和未知项，不承诺固定单次成本。
- 上线前需获得明确的总消费上限、告警接收人及停机负责人；本轮仅规划，不采购 GPU、不充值、不调用付费 API，也不执行任何云端操作。
