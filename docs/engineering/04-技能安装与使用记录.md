### 安全结论的边界

审阅未发现隐蔽密钥外传、下载后直接执行的恶意指令、符号链接或二进制文件。**这不是安全认证**；Markdown 技能同样可能引导不合适的操作。

特别记录：

- `hackathon-engine` 有“用户要求审批门”、禁止子代理、立即公网部署与自动提交等通用措辞。这些不代表本次用户授权，不能覆盖现有 AGENTS 协作规则或外部发布权限。
- `pitch-package` 的 ffmpeg 示例只作参考；文件覆盖与素材授权需在实际使用时检查。
- `python-testing-patterns` 的高级 CI 示例包含向 Codecov 上传 coverage，以及标签引用第三方 GitHub Actions。未执行；以后默认保留本地覆盖率报告，外传前另行确认。
- FastAPI 模板中有 `AsyncClient(app=app)` 和旧异步 fixture/event-loop 写法。新版 httpx 需使用 `ASGITransport`，pytest-asyncio 需按锁定版本配置。它是模式参考，不是已经验证能直接运行的脚手架。
- 模板的 SQLite 测试不能替代本项目 PostgreSQL 租约、锁与并发集成测试。

## ⚙️ 依赖、许可证与未安装项

### 外部依赖没有自动拉入

`pitch-package` 文本会引用 `pitch-deck`、`demo-video`、`pitch-craft`，本次未安装，所以它提供完整准备方法，但**不是已经装好的一键视频/幻灯片生成工具链**。现有 presentation/browser 工具可用于对应工作，实际制作时再选择，无需现在扩充所有依赖。

`hackathon-engine` 引用的 clean-writing/research-method 等独立技能也没有递归安装；它的 11 个本地 references 文档完整。`pitch-package` 的两份本地 references 完整，但 README 中指向仓库父级 README 的链接在单技能安装后不成立，不影响入口文档读取。

`python-testing-patterns/references/details.md` 有一个重复 `references/` 的相对链接；实际 `references/advanced-patterns.md` 文件存在，按正确路径读取即可。本次保留上游参考文件，不为非核心链接扩大修改。

### 许可证

- `hackathon-engine` 锁定提交的仓库 `LICENSING.md` 将原生材料列为 **AGPL-3.0-only**，不能误写为 MIT。[^5]
- `pitch-package` 为 **MIT**。[^6]
- 两个 `wshobson/agents` 技能为 **MIT**。[^7]

安装器只复制技能子目录，未附带仓库根 LICENSE。已在本文保留锁定版本许可链接。个人本地使用与把技能全文放进参赛仓库分发不是同一行为；如要再分发原文或改写副本，应检查许可义务并保留所需声明。本次项目设计为独立撰写，没有把这些技能全文复制到项目或自动把其许可证指定为产品许可证。

### 为什么不继续堆技能

本次未找到足够可信且明确适配 Paper2Run 的官方 Qwen/DashScope 专用技能，故不安装低可信封装；这不等于断言互联网上不存在任何相关技能。接入依据采用阿里云官方接口文档。[^8]

不安装重型 ML pipeline/LangGraph 编排技能，是因为首版已经确定为小规模显式持久状态机，不应让技能反过来改变架构。安全方案参考 Docker 官方文档与项目威胁模型，不因某技能带“security”字样就跳过自身验收。

已有 `frontend-design`、PDF、Playwright、scikit-learn、实验设计等能力不重复安装。四项新增能力补的是参赛组织、后端和测试，而不是改变原有产品定位。
